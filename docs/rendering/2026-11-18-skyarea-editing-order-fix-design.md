## 问题

新放置的音符被追加到 `Chart.Notes` 末尾，`SourceOrder` 为 -1。原实现按源序号
而非时间顺序排列，因此当音符在时间轴上前后移动时，写盘顺序仍沿用旧的源序号。
这导致同一个谱面在编辑状态和保存后的文件中可能读到不同的结果。

`latentduality` FBD 在 67263–67412 ms 与 67412–67676 ms 两段的问题即为实例。

## 修复要点

- `Normalize` 增加 `useOutputOrder` 参数：编辑提交与通知走写盘顺序。
- 输出顺序由 `CompareNotesForOutput` 负责，按 `TimeMs → Kind → StartLane → Id` 排序。
- 读取时优先按文件中的源序号排列；源序号缺失或重复时按上述顺序推。
- 仅在解析保存文件时按时间列表排序，其余场景恢复原有列表顺序与源序号。
- 新放置的音符在提交前确定 `Id`，保证唯一性并支持同时落盘的分支合并。
- 分组只比较顺序中的**上一段** Skyarea，沿用 2 ms 容差与稀疏组号规则。

## 验证

覆盖场景包括：音符的前移、后移与跨段移动，重复的源序号，同时落盘的分支合并，
以及写盘回读的一致性检查。任一实现在不满足前段的检查中失败。

使用真实包做追加覆盖测试：先核对编辑结果与写盘回读，再进行 Unity 编译、
编辑器自检与回归检查，最后复核该问题未复现。
