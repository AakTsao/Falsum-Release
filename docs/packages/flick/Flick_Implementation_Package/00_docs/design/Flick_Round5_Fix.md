# 第五轮：端帽覆盖 / 尾巴亮度 / 斜纹密度 / 高度独立

## 一、"flick 模型应该把 plane 完全罩住"

### 先确认几何事实（从 prefab 精确计算）

`v5-3.prefab` 的实际变换：

| 节点 | localPosition | localRotation | localScale |
|---|---|---|---|
| `v5-3` | (0,0,0) | quat(0,1,0,0) = 绕 Y 180° | (1,1,1) |
| `Plane` | (−0.791, −0.042, 0.0008153589) | ≈绕 Z 180° | **(−1,−1,−1)** |
| `Flick` | (−0.799, −0.045, 0) | identity | (1,1,1) |

代入网格顶点后，**在 root 空间的实际位置**：

| 层 | x 范围 | y 范围 | 尺寸 |
|---|---|---|---|
| **Flick（箭头）** | 0.0008 → 0.2328 | **−0.0069 → 0.1531** | 0.232 × **0.160** |
| **Plane（尾巴）** | 0.0708 → 1.6068 | **0.0010 → 0.1470** | 1.536 × **0.146** |

**关键结论**：箭头在 Y 方向**两端都超出尾巴约 0.007**（−0.0069 vs 0.0010，0.1531 vs 0.1470）。
也就是说 **"箭头完全罩住尾巴的头部"在几何上本来就成立**，不需要改网格。

### 那为什么看起来没罩住？

因为两层**用的是同一个 renderQueue（都是 3012）**，而透明物体的绘制顺序在同队列内**不保证**，
所以箭头有时被画在尾巴下面。

### 修复

把箭头（`Mat.001` / `Mat.001 R`）的队列提到 **3014**，尾巴（`FlickV5`）保持 **3012**：

| 材质 | 队列（前 → 后） |
|---|---|
| `FlickV5 Left` / `Right`（尾巴） | 3012 → **3012** |
| `Mat.001` / `Mat.001 R`（箭头） | 3012 → **3014** |

队列大的后画，所以箭头现在**必定盖在尾巴上**。

## 二、"plane 还是暗了"

### 根因：`_Color` 的蓝通道只有 0.18

材质里的 `_Color` 是白色 `(1,1,1,1)`，但 `NoteRenderer` 在运行时用 MaterialPropertyBlock 写入：

```csharp
new Color(1f, 0.82f, 0.18f, fade)   // 黄色
```

蓝通道 0.18 会把亮度压掉一大截。上一轮加的 `_TailLift` 虽然已在染色之后，
但**单纯乘一个系数救不回丢失的通道平衡**——结果就是"暖但暗"。
而且尾巴区域本来 `_Base` 的 alpha 就偏低，视觉上更暗。

### 修复：尾巴"去染色"混合

新增 **`_TailDetint`**（默认 **0.55**）：

```hlsl
float3 rawRgb = rgb;                              // 保存未染色原色
rgb *= _Color.rgb;                                // 原来的染色
rgb = lerp(rgb, rawRgb, tailW * _TailDetint);      // 尾巴往原色回拉
rgb *= lerp(1.0, _TailLift, tailW);                // 再乘提亮
```

- `_TailDetint = 0`：完全保留染色（最暗/最黄）
- `_TailDetint = 0.55`：**默认**，尾巴明显变亮、仍偏黄
- `_TailDetint = 1`：尾巴直接用原始色（最亮）

同时 `_TailLift` 默认从 1.35 提到 **1.7**。

## 三、"斜纹有点稀疏"

`_BarRepeat` 默认从 **5.5** 提到 **8.0**。

> 这个值是上一轮按原版截图估的（约 5~6 条）。您现在觉得稀疏，说明实际渲染时
> 尾巴在屏幕上的长度比参考截图长，或 `_Color` 压暗后条纹对比度不足显得少。
> 8.0 是折中值，直接在这个参数上继续调即可（建议 8–12）。

## 四、"高度为什么和宽度相关"

**这是我在上一轮引入的错误，已修正。**

上一轮为了修"太高/太矮"，我把 Y 也乘上了 `widthRatio`：

```csharp
// ❌ 上一轮（错）：高度跟着宽度变
visual.FlickPlaneBaseScale.y * widthRatio * FlickTailHeightScale,
```

这导致宽度一变高度就跟着变。正确关系应该是由**两个网格的固有高度**决定的：

| 网格 | 固有高度 | 比例 |
|---|---|---|
| `Flick`（箭头） | 0.160 | 100% |
| `Plane`（尾巴） | 0.146 | **91.25%** |

即**尾巴天生就比箭头矮 8.75%**，且这个比例恒定、与宽度无关。

修正后：

```csharp
// ✅ 现在：X 跟宽度，Y 只用固有值
new Vector3(
    FlickPlaneBaseScale.x * widthRatio,   // 宽度：跟谱面宽度
    FlickPlaneBaseScale.y * FlickTailHeightScale,  // 高度：只跟网格固有比例
    FlickPlaneBaseScale.z)
```

`FlickTailHeightScale` 默认 **1.0**（= 保持 91.25% 的固有比例）。想再矮一点就调小（如 0.95）。
